# Backend design — scaling-octo-eureka

> Source of truth: `drawdesign.md` at the workspace root. This file holds the
> approved backend portion.

## Goal

Spring Boot back end for the Six Kids Crafts gallery: serve a public gallery
of a woodworking business's finished work and let an admin add/update pieces
and upload images over the API — **no code redeploy needed** for content.

No ecommerce. Sales/order-taking is explicitly out of scope.

## Tech

Java 21, Spring Boot 4.x (fresh from start.spring.io, parent version **without**
the `.RELEASE` suffix — e.g. `4.1.1`, central does not publish `4.1.1.RELEASE`),
Maven wrapper, H2 file DB, embedded filesystem storage.

## Runtime storage

- Images: filesystem `./uploads/`, served at `/uploads/**` via a resource
  handler. URL is always derived: `/uploads/<stored_name>`.
- DB: H2 embedded file `jdbc:h2:file:./data/gallery`, `ddl-auto=update` so the
  schema evolves in place across restarts.
- `data/` and `uploads/` are gitignored — content is runtime, never committed.

## Schema

PKs are BIGINT identities (H2-native). Generated by Hibernate (`ddl-auto=update`).

```
gallery_item                  -- a finished piece (MVP core)
  id            BIGINT PK
  title         VARCHAR(200)
  description   VARCHAR(2000) NULL
  category      VARCHAR(100) NULL
  sort_order    INTEGER DEFAULT 0
  published     BOOLEAN DEFAULT FALSE
  created_at    TIMESTAMP
  updated_at    TIMESTAMP

media_asset                   -- uploaded image/video on disk under uploads/
  id            BIGINT PK
  asset_type    VARCHAR(10)               -- IMAGE | VIDEO
  stored_name   VARCHAR(255)              -- URL = /uploads/<stored_name>
  content_type  VARCHAR(100)
  size_bytes    BIGINT
  sort_order    INTEGER DEFAULT 0
  uploaded_at   TIMESTAMP

item_media                    -- join: many images per item, ordered
  item_id       BIGINT FK -> gallery_item.id
  media_id      BIGINT FK -> media_asset.id
  sort_order    INTEGER DEFAULT 0
  PK (item_id, media_id)

app_user                      -- admin accounts (round 2; env creds today)
  id            BIGINT PK
  username      VARCHAR(50) UNIQUE
  password_hash VARCHAR(255)
  role          VARCHAR(20)
  created_at    TIMESTAMP

article                       -- round 2
  id            BIGINT PK
  title         VARCHAR(200)
  slug          VARCHAR(200) UNIQUE
  body_md       TEXT
  featured_media_id BIGINT FK -> media_asset.id NULL
  published     BOOLEAN DEFAULT FALSE
  published_at  TIMESTAMP NULL
  created_at    TIMESTAMP

video                         -- round 2
  id            BIGINT PK
  item_id       BIGINT FK -> gallery_item.id NULL
  title         VARCHAR(200)
  provider      VARCHAR(20)                -- YOUTUBE | VIMEO | URL
  url           VARCHAR(500)
  sort_order    INTEGER DEFAULT 0
  created_at    TIMESTAMP
```

## API contract

Public:
- `GET /api/gallery` → `[{ id, title, description, category, sortOrder, published, createdAt, images: ["/uploads/<name>", ...] }]`
- `GET /api/gallery/{id}` → single item; 404 if missing/unpublished

Admin (basic auth, `ADMIN_USER`/`ADMIN_PASSWORD` env, role `ADMIN`):
- `POST /api/admin/gallery` multipart: part `item` (JSON: title, description, category, sortOrder, published), part `image` optional
- `PUT /api/admin/gallery/{id}` multipart: same parts; a provided `image` is appended as the next image
- `DELETE /api/admin/gallery/{id}` → 204, removes the item and its media files

Note: serving a multipart `item` part with an HTML form needs the part named
`item` and sent as `application/json`.

## Config

- Multipart cap ~20MB per image, ~25MB request.
- CORS allows `http://localhost:5173` (dev frontend).
- H2 console enabled at `/h2-console`.
- New Spring Boot 4 test packages: `AutoConfigureMockMvc` is in
  `org.springframework.boot.webmvc.test.autoconfigure`.
